## 1. 왜 했나 — 분석 결과 요약

### 1.1 센서는 1분마다 쏘지만 값은 ~12분마다 바뀐다
게이트웨이 저널 24시간 분석(동일값 중복 제거 후 값 스텝만 집계):

| 센서 | 값 스텝 간격 중앙값 | 최빈 구간 |
|---|---|---|
| 바닥외부 | 12.2분 | 12–15분 |
| 내부1층 | 12.2분 | 12–15분 |
| 다락 | 12.2분 | 12–15분 |

- 순정은 **2.1초마다** 같은 패킷을 반복(≈30회/분), **61초마다** 새 프레임, 측정값 자체는 **~12분**(드리프트가 빠르면 ~10분) 주기로 갱신. 고정 타이머는 아니고 변화 속도에 따라 10–15분.
- 송신·측정 전력 비교로 이 주기를 설명할 수는 없다(수신 로그로 기기 전력은 측정 불가, 일반적으로 라디오가 측정보다 비쌈).

### 1.2 제어에 미치는 영향 (실측·시뮬)
- 플랜트 열시정수 ≈ 5시간 ≫ 12분 → 안정성엔 문제없음.
- 자연 사이클 7건 실측: 오버슈트 중앙 +0.4°C, 언더슈트 −0.1~−0.7°C, 스윙 ~1.5°C, 1.2회/시.
- **진짜 낭비는 strict `>` 비교 + 값 격자**: 센서가 off_th를 정확히 보고해도 무시 → 다음 갱신(중앙 10.5분, 최대 12.8분)까지 1.7kW 계속 → 사이클당 ~0.24–0.37kWh. → `heater_control.py`의 `decide_relay`를 `>=`/`<=`로 수정(커밋 `c049fd1`).
- 예측(열지연 보상) 제어는 12분/0.5°C 센서로는 **무효 또는 채터링**(실내 dT/dt·외기 피드포워드 모두 시뮬 실패) → 구현했다가 되돌림. 1분 샘플링이면 유효(스윙 1.14→0.61, 예측 결합 0.39°C).
- 컴포트 밴드 0.5°C는 센서 바닥과 일치하는 최적값(넓히면 스윙만 커짐). 유지.

### 1.3 Pi 수신률
콜백에서 카운터 중복제거 직전 8분 기록: 순정 광고주기 2.1 s, 패킷 수신률 **p = 0.70 / 0.65 / 0.76**(바닥/1층/다락). RSSI −28 dBm인 1층이 가장 낮다 → 손실은 거리·RF가 아니라 **수신기(BlueZ 스캔 듀티)** 쪽 ~30% 고정. 순정은 30회 반복으로 이를 가렸다. pvvx에선 **측정 배수 = 복제 횟수**이므로 배수 4가 필요(누락 (1−p)^4 ≤ 1.5%).

## 3. B1.6 플래시 절차 (실제로 통한 순서)
다락은 **B1.6 / 2.1.1_0159**(플래셔 표시). 11-08 확인: 1층·바닥은 **B1.5**(11-07의 "셋 다 B1.6" GATT 원격 판독은 틀렸음). 0159c 선행 플래시는 HW가 아니라 **펌웨어 2.1.1_0159** 때문이라 B1.5에도 그대로 필요하다. pvvx README는 B1.6을 "비권장(전류↑·저대비 LCD)"으로 표시하지만 v5.3+에 전용 빌드가 있다.

준비: Chrome `chrome://flags` → Experimental Web Platform features ON. 센서 1 m 이내, 배터리 ≥40%(연결 중 전압 2.9 V대면 충분).

1. [TelinkMiFlasher](https://pvvx.github.io/ATC_MiThermometer/TelinkMiFlasher.html) → **Connect** → `LYWSD03MMC` → HW/FW 표시 확인(B1.6 / 2.1.1_0159).
2. **Login**: 기기ID(`blt.…`)·Mi Token·Bind Key 입력 → `Login successful`.
3. **`Original_OTA_Xiaomi_LYWSD03MMC_v2.1.1_0159c.bin`** → Start Flashing. 겉보기(이름·버전·LCD)는 원본과 동일하다. **이 단계를 건너뛰고 ATC를 직행하면** 플래시 성공처럼 보이지만 **연결을 끊으면 침묵하고 전원을 빼면 순정으로 복귀**한다(실제 재현).
4. **Reconnect → Login 다시 → `ATC_v59.bin`** → Start Flashing(47초) → 재부팅 → 목록에 **`ATC_328C21`**(MAC 끝 6자리).
5. 설정(Configuration): Advertising type **MIJIA (MiHome)**, **Encrypted beacon ON**, Advertising interval **5 s**, Measure interval **×4**(=20 s), 나머지 기본값 → Set Config.
6. **Keys and Codes → Get BindKey**: 플래시 후 EEP 키가 클라우드 키와 **달라져 있었다** → 문서의 BLE Key를 넣고 **Set BindKey**. 이걸 해야 게이트웨이가 무수정으로 복호화한다.
7. **Disconnect**(연결 중엔 광고가 멈춰 게이트웨이가 못 받음).
8. 합격 판정: **배터리 분리 10초 → 재장착** 후 선택창 이름이 `ATC_328C21`, 플래셔 Software Version 5.9. (순정 복귀면 `LYWSD03MMC` / 2.1.1_0159.)

알아둘 것: pvvx는 B1.6을 **"B1.1"로 표시**(오감지, 정상). LCD는 정상 동작했다. 순정 복귀는 플래셔의 Original 버튼으로 가능.

## 10. 예측(열지연 보상) 제어 — 1분 샘플링 기준 재검토

11-07엔 12분/0.5°C 센서로는 무효·채터링이라 되돌렸다(1.2절). 세 센서가 1분 갱신이 된 11-08, 2노드 플랜트(센서 주변 공기 C_a 0.40 MJ/K ↔ 축열체 1.15 MJ/K, 결합 900 W/K, UA 47 W/K, 히터 1770 W, 히터 지연 1.5분, 센서 지연 5분)를 **11-07 저녁 실측**(12분 센서: 사이클 1.2/h·ON 51%·승온 2.7°C/h)에 맞춰 보정하고 비교했다(`sim_pred4.py`).

외기 0.7°C, 컴포트 23/23.5:

| 케이스 | 사이클/h | 스윙 | 오버슈트 | 평균편차 | kWh/일 |
|---|---|---|---|---|---|
| 순정 12분, 히스테리시스 | 1.5 | 2.06 | +0.62 | 0.46 | 24.7 |
| **pvvx 1분, 히스테리시스(현행)** | 2.4 | 1.21 | +0.27 | 0.33 | 25.1 |
| 1분 + 예측 lead 3분 | 3.2 | 0.99 | +0.19 | 0.25 | 24.7 |
| 1분 + 예측 lead 5분 | 3.8 | 0.89 | +0.10 | 0.21 | 24.7 |
| 1분 + 예측 lead 8분 | 4.2 | 0.70 | −0.02 | 0.21 | 24.7 |

(예측 = 최근 5분 보고값의 최소자승 기울기 × lead를 보고값에 더해 히스테리시스 판정, 보정량 ±0.5°C 제한. 외기 4°C에서도 같은 경향.)

**장점**
- 쾌적성: 스윙 1.2 → 0.9°C, 오버슈트 0.27 → 0.10, 목표 대비 평균편차 0.33 → 0.21°C.
- 1분 샘플링 덕에 기울기 추정이 안정적 — 12분 센서 때의 채터링·무효 문제는 사라짐.

**단점·한계**
- **전력 절감 없음**(≤0.4 kWh/일, 1.5%): 손실은 평균 실온이 정하고 평균은 같다. 에너지 목적이면 의미 없음.
- 릴레이 사이클 2.4 → 3.8/h. 예측은 본질적으로 밴드를 좁히는 것과 같아 더 자주 끊는다. 최소 ON/OFF 5분 제약은 걸리지 않음(사이클이 이미 ~15분).
- lead 8분 이상은 언더슈트로 넘어가고 사이클만 는다 → 쓴다면 lead 3–5분.
- 가장 큰 이득은 이미 **1분 샘플링 자체**가 가져왔다(스윙 2.1 → 1.2, 12분 늦게 끄는 낭비 제거).

**판단**: 현행(1분 + 히스테리시스)으로 2–3일 실측 후 결정. 실측 오버슈트가 모델처럼 +0.3이면, ±0.4°C 쾌적성을 위해 lead 3–5분 + 최소 OFF 8분(사이클 ≤3/h)으로 넣을지 사용자 선택. 기본 권고는 "지금은 보류".

- 실측 ON 횟수: 11-01 3, 11-02 4, 11-06 3, 11-07 10회(종일 재실·12분 센서). 주말 재실 패턴이라 평일 동파모드는 거의 동작 없음.

- Tuya 16 A 플러그 릴레이 전기적 수명 3만–10만 회(정격 16 A 저항부하), 부하 8 A → 릴레이 접점은 **5–15겨울**. 접점 소모는 수명을 정하지 않는다.
- 실제 약점은 **전원부 전해콘덴서**(농막 온도 폭 −10~40°C)와 **8 A 장시간 통전 발열** → 현실적 수명 **3–5년**. 한 시간 ON 뒤 플러그 몸체 온도 확인(≤45°C 정상).
- 고장 모드: 대부분 OFF로 죽음(동파 위험, `fault_min_watt` 감시·음성 알림으로 감지됨), 드물게 ON 고착(히터 자체 과열 차단 확인).
- 보강안: ① 예비 플러그 미리 페어링·키 추출해 농막 보관 ② Shelly Plug S / 1PM(로컬 API·내열 우위) ③ Shelly 1 + DIN 접촉기 20 A(접촉기가 부하 담당, 수십만 회). 2 kW를 한 겨울 돌릴 거면 ②가 합리적.

## 12. 남은 후속
1. 2–3일 실측(1분 센서 사이클·오버슈트) → 예측제어 도입 여부.
2. 기상 타이머(취침 → 컴포트 자동 전환, 예 05:15): 아침 23°C 도달이 1시간 걸리는 건 히터 1.74 kW − 손실 1.0 kW = 0.7 kW뿐이라 구조적. 설정파일 `wake` 블록 + ~20줄.
3. 배터리 추세(농막_배터리) 2주 → 1층·바닥 전지 교체 시점, pvvx 소비율 실측.
4. 예비 플러그 / Shelly 전환 검토.
