# LTE 동글 Huawei E3372h-607 — 개통·시험 기록 (2026-11-13, 집 PC)

> 농막 상시 인터넷용 LTE USB 동글을 집 윈도우 PC에 꽂아 두 유심(KT망 100 GB·6 GB)으로 시험한 기록과 현장 절차.
> 비밀값(유심 번호·전화번호·문자 내용)은 쓰지 않는다. APN은 통신사 공개값이다.
> 관련: 계획 [NETWORK_MIGRATION.md](../NETWORK_MIGRATION.md) §5, 데이터 감시 [TELEGRAM.ko.md](TELEGRAM.ko.md) "데이터 사용량 감시"(`notify/data_watch.py`).

## ⭐ 안테나가 필요한가 — 현장 검사법 (농막 도착하면 먼저)

> **결론(집 시험)**: 도시 집에서는 안테나 없이도 지장 없었다. 농막은 시골이라 기지국이 멀어 더 약할 수 있으니 **현장에서 재 보기 전까지는 안테나를 단다.** 안테나를 달면 신호가 약 12~14 dB 좋아졌다(여유 = 날씨·계절에도 안 끊김).

**검사 (5분)**
```
python3 scripts/lte_signal_check.py 60 안테나      # 안테나 단 채로 1분
python3 scripts/lte_signal_check.py 60 무안테나    # 안테나 빼고 1분
```
동글이 꽂힌 기기(Pi·PC)나 같은 네트워크에서 실행한다. 관리 화면 대신 Home → 신호 막대, 또는 System → Device Information의 RSRP·SINR를 눈으로 봐도 된다.

**판정 기준 — 안테나를 뺀 상태의 1분 중앙값으로**

| RSRP | 판정 |
|---|---|
| **−100 dBm 이상** | ✅ 안테나 없이 써도 됨 |
| **−100 ~ −105 dBm** | ⚠ 쓸 수는 있지만 여유가 없음 → **안테나 권장** |
| **−105 dBm 미만** | ❌ **안테나 필수**. 그래도 약하면 창가·높은 곳으로 옮기고, 그래도 −110 아래면 더 큰 외장 안테나 |

- 아래 중 하나라도 있으면 **한 단계 더 엄하게** 본다: SINR 중앙값 **−3 dB 미만**, 측정 중 **연결 끊김**, 1분 사이 **기지국(Cell ID)이 바뀜**.
- 안테나 없이 "✅"여도 **하루 동안 끊김이 없는지** 확인한 뒤에 뺀다(무인 농막은 한 번 끊기면 일주일을 모름).
- 집 측정 예: 안테나 없음 RSRP −99 / SINR −1(경계), 안테나 있음 RSRP −85~−87 / SINR −1~−2 → 도구 판정 ✅.

## 4. 알아낸 것

1. **유심을 새로 넣으면 첫 등록에 동글 재시작이 필요했다**(두 유심 모두). 현장 절차와 자동 복구에 반영.
2. **APN 프로필이 비어 있으면 데이터가 안 붙는다.** KT망은 `lte.ktfwing.com`. 프로필은 동글에 저장돼 유심을 바꾸거나 Mango·Pi로 옮겨도 유지된다.
3. **경로가 둘이면 조용히 넘어간다.** PC의 Wi-Fi가 끊기자 윈도우가 기본 경로를 LTE로 바꿔 이메일·배경 통신 등 27 MB가 LTE로 나갔다. 경로 우선순위는 Wi-Fi 50, LTE 75. → 집 PC는 시험 뒤 동글을 뽑거나 "종량제 연결"로 지정. 농막은 데이터 감시 필수.
4. microSD 슬롯은 USB 메모리 기능일 뿐 인터넷과 무관. 농막에선 끼우지 않는다.
5. 관리 API(`/api/webserver/SesTokInfo`로 세션·토큰 → `/api/monitoring/status`, `/api/net/current-plmn`, `/api/device/signal`, `/api/net/plmn-list`, `/api/dialup/profiles`, `/api/dialup/dial`, `/api/device/control`)로 상태 읽기·재시작·APN 설정을 모두 할 수 있다. 응답은 XML. 연결 상태 901=연결, 902=끊김. 서비스 상태 2=정상, 1=제한.

## 5. 현장 절차

**농막 도착**
1. 유심 A(100 GB)를 동글을 뽑은 상태에서 넣는다(방향 확인).
2. 외장 안테나 2개를 달고, 창가·높은 곳에 둔다.
3. Mango(또는 Pi)에 꽂고 2분 기다려 **하늘색 켜짐** 확인. 녹색 깜빡이면 한 번 뽑았다 다시 꽂는다.
4. 신호를 잰다: RSRP가 −105 dBm보다 약하면 위치를 옮기거나 더 큰 외장 안테나 검토.

**떠나기 전(유심 B로 바꿀 때)**
1. 동글을 뽑고 유심 B(6 GB)로 교체 → 다시 꽂고 2분 → 하늘색 확인(안 되면 재꽂기).
2. **폰 LTE로 바깥에서 확인**: 시트 현재값이 갱신되는지, 또는 Tailscale로 Pi 접속. 불빛만 믿지 않는다.
3. 데이터 감시(`data_watch`)의 `limit_gb`를 유심에 맞춘다: 유심 A면 100(또는 경보만), 유심 B면 6.

## 6. 남은 일

- Mango 도착 → OpenWrt에서 동글을 WAN으로(cdc_ether), 고정 주소, Pi 연결.
- **자동 복구**: 인터넷이 몇 분 이상 끊기면 동글 재시작(`/api/device/control`), 그래도 안 되면 USB 전원 재인가. 유심 교체 뒤 첫 등록 실패도 사람 없이 풀린다.
- 6 GB 소진 뒤 동작(감속인지 차단인지) 요금제 조건 확인.
- 2027-05: 유심 A 조건 종료 전 사용량 기록을 보고 회선 결정.

## 7. 관리 화면 정보 (System → Device Information 등)

- **공개 금지**: IMEI(동글 고유번호), IMSI(가입자번호), ICCID(유심 카드번호), My number(전화번호). 문서·저장소·대화방에 올리지 않는다.
- **WAN IP가 `10.`으로 시작** → 통신사 내부 공유 주소(CGNAT). 바깥에서 농막으로 바로 못 들어온다 → 원격 접속은 Tailscale. 동글의 포트 포워딩(Virtual Server)·DMZ는 소용없다.
- **Cell ID / eNB / PCI**: 붙은 KT 기지국 번호. 농막에서 신호가 불안정할 때 기지국이 자꾸 바뀌는지 본다.
- **NAT 설정은 Cone 유지**: Tailscale이 기기끼리 직접 연결하기 쉬움(Symmetric이면 중계 서버를 거쳐 느려짐). 주소 변환이 통신사→동글→Mango 세 겹이어도 일반 사용·Tailscale엔 문제없음.
- **Wi-Fi AP 아님**: 동글은 USB로 꽂힌 기기 하나에만 인터넷을 주는 작은 공유기다. Shelly·Home Mini·Qingping은 Mango(또는 Pi)가 뿌리는 Wi-Fi에 붙는다.
- **네트워크 설정은 Auto 유지**(LTE 우선, 안 되면 3G; 전 대역). 시골에서 LTE↔3G를 오가며 끊기면 LTE only, 대역이 흔들리면 B8(900 MHz) 고정을 검토.
- **APN 프로필**(KT-LTE, `lte.ktfwing.com`, IPv4)은 지우거나 바꾸지 않는다. 지우면 데이터가 끊긴다.
- **USSD(*100#)**: 해외 선불 잔액 조회용. 국내 통신사는 대부분 지원 안 함 → 남은 데이터는 통신사 앱, 동글 Statistics, `data_watch` 텔레그램 경보로 본다.
- **관리 비밀번호**: 지금은 로그인 없이 열린다(같은 Wi-Fi의 누구나 APN 삭제·재시작 가능). 농막 설치 때 걸되, `data_watch`·자동 재시작·`lte_signal_check`가 로그인하도록 함께 고친다.

| 항목 | 자료 기준 | E3372h-607과 비교 |

| 형태 | **USB 동글 + Wi-Fi 공유기 내장**(최대 10대) | E3372는 USB로 꽂힌 기기 하나에만 인터넷 |
| 전원 | USB(충전기·보조배터리)면 단독 동작 | 같음 |
| LTE | Cat.4, 150/50 Mbps | 같음 |
| 대역 | 자료마다 다름: B1/3/5/7/8/20 또는 B1/3/7/8/20/38 → **KT B1·B3·B8은 둘 다 포함** | |
| Wi-Fi | **2.4 GHz만**(5 GHz라는 판매 글은 신뢰 낮음) | 없음 |
| 외장 안테나 | **TS-9** 단자 2개 | ⚠ 화웨이 E3372 계열은 보통 **CRC9** → **E3372 안테나가 안 맞을 수 있다**. 상자에 TS-9 안테나가 있는지 확인 |

**E3372에서 배운 것 — MF79U에서도 먼저 확인**
1. APN이 비어 있으면 데이터가 안 붙는다 → KT망 `lte.ktfwing.com`.
2. 유심을 새로 넣으면 첫 등록에 재시작이 필요할 수 있다.
3. 노트북에 꽂아 시험하면 Wi-Fi가 끊길 때 윈도우가 조용히 LTE로 넘어간다 → **USB 충전기에 꽂아 Wi-Fi로 시험**한다.
4. 관리 비밀번호·Wi-Fi 비밀번호를 기본값에서 바꾼다(ZTE 기본값이 `admin`인 경우가 많음 — 미확인).

**쓰임새 제안 — 유심 교체 없애기**

| 기기 | 유심 | 역할 |
|---|---|---|
| E3372(농막 고정) | **유심 B 6 GB** | Pi·Shelly·Home Mini 상시 인터넷. **바꿔 꽂지 않는다** |
| MF79U(휴대) | **유심 A 100 GB**(소진 뒤 5 Mbps) | 내 노트북·휴대폰 Wi-Fi. 농막에 가져가도 그대로 |

**도착 시험(15분)**: 유심 A 넣기 → USB 충전기에 꽂기 → 라벨의 Wi-Fi로 휴대폰 연결 → 관리 화면에서 통신사·4G·신호·APN 확인(비면 `lte.ktfwing.com`) → Wi-Fi·관리 비밀번호 변경 → 속도 1회.

- 집처럼 신호가 약한 곳에서도 E3372보다 빠르다. 농막은 신호가 훨씬 좋아(E3372 SINR 21~25 dB, 27 Mbps) 더 나올 것.
- '부하 중 반응성 낮음' = 크게 받거나 올리는 동안 지연이 수 초로 늘어나는 LTE 동글의 흔한 버퍼 현상. 영상 통화 중 큰 업로드를 피하면 된다(히터·센서 제어에는 영향 없음).
- 신호: **RSRP −100 dBm**(관리 화면) — 같은 집 E3372 안테나 없음 −99 dBm과 같은 수준(약함 경계). 신호는 같은데 속도가 1.6배 → 동글 성능 차이 또는 측정 시점 차이. SINR은 아래.
- 관리 화면(확인): 주소 **192.168.0.1**(`ufi.ztedevice.com`), 2.4 GHz 최대 10대, 펌웨어 `BD_XCBZHKMF79UV1.0.0B03`, KT·LTE. 상세 화면에 SINR·RSRQ·밴드는 없음(이 펌웨어) → 맥에서 `curl -s -H "Referer: http://192.168.0.1/index.html" "http://192.168.0.1/goform/goform_get_cmd_process?isTest=false&multi_data=1&cmd=network_provider,network_type,lte_rsrp,lte_rsrq,lte_snr,lte_band,wan_apn,signalbar"`(로그인 없이 됨, IMEI·IMSI 안 읽음).
  - 집 결과: KT·LTE, **RSRP −100 · RSRQ −7 · SINR 7.0 dB** · 막대 4. 밴드·APN은 빈칸(APN 비어도 KT가 자동으로 붙여 줌 — 손댈 것 없음).
  - **외장 안테나(E3372 동봉, TS9 → MF79U TS9 단자에 맞음), 11-17 00:38, 10초 간격 8회**: RSRP **−86~−87**(없을 때 −100 → +14 dB) · RSRQ −8~−12 · SINR **2~6 dB**(없을 때 7) · 막대 5. 신호는 커졌지만 간섭도 함께 커져 SINR은 오르지 않음 → 속도 이득은 작을 수 있음(같은 시각 안테나 있/없 속도 비교로 판단).
  - 같은 집 E3372는 SINR −1 dB → **신호 크기는 같아도 SINR이 8 dB 좋아** 속도가 1.6배였던 이유. 농막 시험 때도 이 명령으로 기록.
- 망 주소가 겹치지 않음: 동글 192.168.0.x · E3372 192.168.8.x · 농막 Ryufarm 10.42.0.x → Pi가 wlan0으로 동글에 붙어도 충돌 없음.
- WAN 주소가 10.x(통신사 사설망, CGNAT) → 바깥에서 들어오는 접속은 안 됨. Tailscale·텔레그램은 안에서 나가는 연결이라 영향 없음.
- ⚠ 관리 화면에 전화번호·IMEI·IMSI가 그대로 보인다 — 화면 캡처를 공유할 때 가릴 것(이 문서엔 적지 않음).
- Wi-Fi 비밀번호 스티커는 겉면이 아니라 뚜껑 안쪽.

참고: aio.lv·4gltemall·lambda-tek 사양, ZTE MF79U 설명서(manualslib·manuals.plus), OpenWrt 포럼(MF286보다 MF79U가 안정적이라는 사용자 보고).

## 8. 농막 현장 (2026-11-15, Pi에 연결)

- Pi(리눅스)는 동글을 **자동으로 HiLink 모드(12d1:14dc)로 전환**하고 `cdc_ether`로 `eth1`(192.168.8.100)을 만든다. NetworkManager가 기본 경로를 LTE로 잡았다(metric 101, 휴대폰 핫스팟 wlan0은 600으로 예비). APN 프로필은 동글에 남아 있어 손댈 것 없음.
- 농막 신호(100 GB 유심, `scripts/lte_signal_check.py` 1분):

| 상태 | RSRP | SINR | 판정 |
|---|---|---|---|
| 외장 안테나, 땅쪽 | −90 dBm | 25.5 dB | ✅ |
| 외장 안테나, 위로 세움 | −91 dBm | 24.0 dB | ✅ |
| **안테나 없음** | **−81 dBm** | 21.5 dB | ✅ |

- **결론: 농막에선 외장 안테나를 빼고 쓴다.** 외장을 꽂으면 내장 안테나가 끊기는데, 동봉 안테나가 내장보다 약 10 dB 나빴다(방향과 무관). 커넥터가 TS9이면 동글의 CRC9 단자와 접촉이 나빠 생기는 전형적 증상. 쓸 일이 생기면 CRC9 단자 안테나를 따로 구한다.
- 시골이라 간섭이 적어 **SINR이 집(−1 dB)보다 훨씬 좋고**, 내려받기 약 27 Mbps(집 7.8).
- 농막 망: 동글(eth1) → Pi(NM shared, eth0 10.42.0.1) → 버팔로 AP "Ryufarm" → 기기들. Pi의 Wi-Fi는 AP를 하지 않아 BLE 수신 저하 없음.
- `data_watch` 한도 100 GB·주기 시작 13일(개통일 가정)로 설정. 6 GB 유심으로 바꿀 때 `heater_config.json`의 `data_watch.limit_gb`를 6으로.
- 휴대폰 핫스팟을 끈 상태(=떠난 뒤 조건)에서 Pi 인터넷·Tailscale(smartcabin)·텔레그램·시트 업로드·서비스 6개 정상 확인.

## 9. 6 GB 유심 교체·장애 대비·기기 인터넷 차단 (2026-11-15~16 밤)

- **유심 교체**(100 GB 9244 → 6 GB 7506): 유심 인식(257, PIN 없음)됐지만 등록 안 됨(902, 신호 0) → HiLink API로 **동글 재시작 40초 뒤 등록**(KT LTE, RSRP −80, SINR 23). 유심을 바꾸면 첫 등록에 재시작이 필요하다는 패턴 재확인.
- 동글의 '이번 달 사용량'은 유심과 무관하게 누적 → `/api/monitoring/clear-traffic`로 지움. `heater_config.json` `data_watch` = 6 GB·매월 1일·폭주 200 MB/h.
- **노트북을 Ryufarm에 붙이면 시간당 160~210 MB**(윈도·Home Mini 업데이트). 같은 날 휴대폰 요금제 7 GB도 소진(핫스팟으로 노트북 사용) → 1 Mbps.
- **넘어감 시험**(동글 데이터만 끔, USB는 살아 있음, 휴대폰 핫스팟 켬): 3분 동안 기본 경로는 계속 LTE(metric 102), NM 연결 검사도 eth1 'full' 유지. Pi 전체 인터넷이 되는 듯 보였지만 **핫스팟의 IPv6로 나간 우연**(구글·텔레그램·Tailscale) — IPv4는 죽은 LTE로 감. 즉 등록만 풀린 경우엔 자동 전환 안 됨(떠난 뒤엔 핫스팟이 없어 무관).
- **자가 복구 `notify/lte_watch.py`**(cron 5분): eth1로 generate_204 두 곳 확인 → 연속 3회 실패면 데이터 켜기 + **동글 재시작**(30분 간격, 하루 8회), 넘으면 '현장 확인' 알림 한 번. eth1이 없으면(동글 빠짐) 알림만. 알림은 텔레그램 대기열(끊긴 동안 쓴 것도 복구 후 전송). 실전 시험: 데이터 끔 → 3회째 재시작 → 30초 뒤 복구, 알림 2건.
- **기기 인터넷 차단 `scripts/farmhut-wan-guard`**(nftables, root, 설치 `sudo bash scripts/install_wan_guard.sh`): Ryufarm(eth0) → LTE(eth1) 전달을 MAC으로 거름. Pi 자신·Ryufarm 안 기기끼리·핫스팟 경로는 그대로.
  - 항상 허용 `/etc/farmhut/wan_allow`: Shelly 히터 플러그(가드의 기상청 예보·SNTP).
  - 한도 `/etc/farmhut/wan_quota`(MAC 하루MB 한달MB # 이름): Home Mini 50/500(음성·알림은 늘 되고 유튜브 음악은 한도에서 끊김), Tuya 선풍기·보조 히터 각 5/30(클라우드 유지 → 앱이 Pi 고장 때 예비 리모컨). 연결 단위 표시(ct mark)로 **올리기+내려받기** 합계, 사용량은 매분 `/var/lib/farmhut`에 저장해 재부팅·재적용 뒤에도 이어 셈, 하루=자정·한 달=1일 초기화.
  - 나머지(노트북·휴대폰 등) 차단. 텔레그램·시트·Pi 터미널 `공유 [N시간|N분|끔|상태]`로 잠깐 열기(최대 24시간, 끝나면 자동 차단, 연 동안은 한도에 안 셈). 한도 첫 도달 시 텔레그램(`notify/wan_tick.sh`, cron 매분).
  - nft 함정 두 가지: 체인 이름 `fwd`는 예약어라 문법 오류, bash `${m:+...{ ... }}`는 안쪽 `}`에서 끝나 버림 → 따로 만들기. 설치 전 `nft -c -f`(일반 사용자도 문법 검사 가능)로 확인.

## 10. 들고 다니는 Wi-Fi 동글을 '재실 때 1순위'로 (2026-11-16, Ryuspot으로 미리 시험)

사람이 있을 때는 들고 온 Wi-Fi 동글(100 GB·5 Mbps 무제한 유심)로 Ryufarm 기기 전부가 나가고, 동글을 들고 떠나면 자동으로 LTE(6 GB)+차단·한도로 돌아가게 한다. 기기들은 Ryufarm에만 붙어 있으면 된다.

- 원리: Pi가 동글 Wi-Fi에 손님으로 붙고(wlan0), 경로 우선순위 50 < LTE(eth1) 100대. 차단·한도 규칙(farmhut-wan-guard)은 **eth1로 나가는 것만** 거르므로 wlan0으로 나가는 동안은 자동으로 제한 없음. NM shared의 MASQUERADE는 나가는 장치와 무관.
- 도구 `scripts/wifi_uplink.sh <연결|SSID> primary|backup|status` (NM 권한으로 sudo 불필요).
- 재실 감지 SSID 여러 개: `gateway.env`의 `GW_PRESENCE_SSID=Ryuspot,<동글SSID>`.
- `공유 상태` 첫 줄에 지금 인터넷 경로(LTE 동글 / Wi-Fi …).
- **시험(Ryuspot을 primary로)**: Pi·Ryufarm 기기 모두 wlan0으로(노트북도 제한 없이 인터넷, Tailscale 직접 연결) → 핫스팟 끔 → 즉시 LTE·차단 적용, 텔레그램·히터 정상 → 다시 켬 → 1분 안에 스스로 다시 붙어 1순위 복귀. 끝나고 Ryuspot은 backup(600)으로 되돌림.
- **주의**: Ryufarm에 붙은 '차단 대상' 기기(노트북)는 동글이 꺼지는 순간 인터넷이 끊긴다. 이 노트북에서 Claude로 작업할 때 두 번 끊김 → 작업용 노트북은 동글/핫스팟에 직접, 또는 '공유'를 먼저 연다.

**11-16 결정: Ryuspot(휴대폰 핫스팟)도 1순위로 상시 설정**(`scripts/wifi_uplink.sh hotspot primary`, NM 연결 설정에 저장 → 재부팅해도 유지).
핫스팟이 켜져 있으면(=사람이 있으면) Ryufarm 기기 전부가 휴대폰 데이터로 제한 없이 나가고(노트북을 Ryufarm에 붙인 채 Claude 작업 확인),
핫스팟을 끄거나 들고 떠나면 자동으로 LTE+차단. 휴대폰 요금제 데이터를 쓰므로 소진 시 1 Mbps.
동글이 오면 동글과 Ryuspot이 둘 다 보일 때 동글을 먼저 고르도록 autoconnect-priority를 동글 쪽을 높게(예: 동글 40, 핫스팟 30) 조정할 것.

**동글 도착 시 절차**
1. `ssh -t pi nmcli --ask device wifi connect "<SSID>"` (비밀번호 직접)
2. `ssh pi '~/smart-cabin/scripts/wifi_uplink.sh "<SSID>" primary'`
3. `gateway.env`에 `GW_PRESENCE_SSID=Ryuspot,<SSID>` → `sudo -n systemctl restart farmhut-gateway`
4. 시험: 동글 켬(경로 wlan0) → 끔(LTE+차단) → 켬(복귀). 동글 채널은 Ryufarm 2.4 GHz와 겹치지 않게(또는 5 GHz).
