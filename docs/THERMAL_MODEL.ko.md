# 농막 열 모델 학습 계획과 데이터 (2026-11-08 시작)

> 목표: 히터·실내외 온도·기상 데이터로 **이 집의 열 파라미터**(열용량·손실·층간 결합·일사 이득)를 학습하고, 그 값으로 날씨 예보 기반 난방 스케줄러를 돌린다. 데이터는 Pi 로컬 CSV에 자동으로 쌓이며, 학습은 오프라인(scp 후 피팅).

## 1. 모델 — 2노드 그레이박스
```
C1·dT1/dt = P·u − UA1·(T1−To) − G12·(T1−T2) + a·I(t) + Q_int
C2·dT2/dt = G12·(T1−T2) − UA2·(T2−To)
```
T1 내부1층, T2 다락, To 바닥외부(외기), u 히터 ON(0/1), P 실측 W, I(t) 일사(대전 ASOS 수평면 일사 + 부여 일조·운량 보정), a 유효 채광 면적(m²), Q_int 재실 내부발열.
학습 파라미터 6개: C1, C2, UA1, UA2, G12, a (+Q_int). 초기치는 `heater_config.json preheat`의 UA 47 W/K·τ 9.16 h(=C/UA 1.55 MJ/K)를 두 노드에 나눠 쓴다.

- 학습: 10분 리샘플 데이터로 1시간 선행 예측 오차 최소자승(`scipy.optimize.least_squares`), 가열 구간(히터·C 정보)과 냉각 구간(UA·성층 정보)을 구분해 피팅.
- 검증: 홀드아웃 날짜의 1 h·6 h 선행 RMSE. 기준선 = 현재 상수 모델. 합격 조건: 11-07(맑음, 23°C 도달 1h50)과 11-08(흐림, 2h30)을 둘 다 재현.
- 식별 조건: 히터 ON/OFF 사이클, 맑은 날과 흐린 날(a 분리), 바람 센 날(UA), 무가열 야간 냉각(C/UA).

## 9. 드리프트 줄이기 — 우선순위 정리 (논의 결론)

"센서 정확도 + 히터 용량"이 답이라는 명제에 대한 검토:
1. **센서 "정확도"가 아니라 "지연"**이 드리프트를 만들었고(12분 → 1분으로 해결), 남은 ±0.1은 케이스 열지연·0.1 격자라 정확도 향상으로는 안 줄어든다.
2. **히터 용량 확대는 드리프트엔 역효과**: 오버슈트 = 가열 속도 × 지연이라 큰 히터는 같은 지연에도 더 지나친다. 용량이 해결하는 건 한파의 정상상태 오차(도달 불가)와 복귀 속도.
3. **근본 해법은 변조**: 손실(~1 kW)에 공급을 맞출 수 있으면 사이클 자체가 사라진다 — 2단 히터(예 1.0 + 0.7 kW, 플러그 2개), PTC 단수, SSR PWM. 예측제어는 변조를 타이밍으로 흉내 내는 싼 대체품이라 이득이 제한적.
4. 우선순위: **지연 제거(완료) → 분배(선풍기/성층) → 변조(2단 히터) → 용량(한파·2구역화와 함께) → 예측제어(비대칭, 맨 뒤)**. 큰 히터 하나보다 작은 히터 둘이 드리프트·용량 모두에 낫다.

`fan` 열: 작업폴더 `fan_on` 파일 유무로 기록(`touch`/`rm`). 11-08 08:22 이후 소급 1.
