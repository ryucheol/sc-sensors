# Google Home Mini — 농막 음성 알림·음성 제어 설계와 집 시험

> 2026-11-13 작성. 농막에 가져갈 Google Home Mini를 집에서 시험한 결과와 활용 설계.
> 집에는 AI 스피커가 여러 대 있어, 시험·운영 모두 **이름과 모델이 정확히 한 대로 맞을 때만** 소리를 낸다.

## 1. 기기

| 항목 | 값 |
|---|---|
| 모델 | Google Home Mini 1세대(H0A, 2017), 마이크로 USB 전원, 옆면 마이크 끄기 스위치 |
| 이름(캐스트) | "Living room" |
| 펌웨어 | 캐스트 빌드 3.78.540761, 로캘 ko |
| Matter | Wi-Fi Matter 기기용 허브로 지원(구글 2022-12 업데이트, 공식 목록에 있음). Thread는 안 됨 — 우리 기기는 모두 Wi-Fi라 무관 |
| 블루투스 | 블루투스 스피커(오디오 수신) 됨 |
| 전제 | 음성 인식은 클라우드 → **인터넷(LTE) 필요**. 처음 Wi-Fi 설정도 폰 Google Home 앱과 인터넷 필요 |

집의 캐스트 기기(참고): "Acorn's speaker"(Google Home, 큰 것), "Living room"(이 Home Mini), "All speakers At Home"(스피커 묶음). 다른 회사 AI 스피커는 캐스트 기기가 아니라 대상이 될 수 없다.

## 2. 캐스트와 블루투스의 차이

| | 캐스트 | 블루투스 |
|---|---|---|
| 통로 | Wi-Fi(같은 공유기) | 기기끼리 직접(약 10 m) |
| 동작 | "이 주소의 음성 파일을 틀어라" 명령만 보냄 → 스피커가 파일을 직접 받아 재생 | 소리를 실시간으로 계속 흘려보냄 |
| 연결 | 재생할 때만 | 계속 유지 |
| 사람 개입 | **처음 Wi-Fi 연결 한 번**. 그 뒤 Pi가 이름·모델로 자동 탐색 | 페어링 모드 진입에 사람 필요("헤이 구글, 블루투스 페어링" 또는 앱). 지금 펌웨어는 내부 API로 페어링을 자동화하기 어려움 |

## 3. 집 시험 (11-13, PC에서)

| 시험 | 결과 |
|---|---|
| 캐스트 탐색 | mDNS로 3대 발견, 이름+모델로 Home Mini 한 대만 선택 |
| 캐스트 재생 | PC 웹서버의 WAV(윈도우 한국어 음성 Heami)를 Home Mini가 받아 재생 → 들림 |
| 블루투스 재생 | PC와 페어링(Home Mini 블루투스 주소 앞 3바이트가 Wi-Fi 주소와 같아 같은 기기로 확인) → 들림 |
| 첫 무음의 원인 | 스피커 **볼륨이 0**이었음. 지금 70 % |
| 블루투스 중 소리 끊김 | 캐스트로 볼륨 변경 접속 + 윈도우 출력 장치를 바꿨다 돌린 뒤, "연결됨"인데 무음 → 블루투스를 끊었다 다시 연결하니 정상 |
| **블루투스 연결 중 캐스트 재생** | **안 됨.** 블루투스 수신 중에는 Home Mini 안에서 "Bluetooth Audio" 캐스트 앱이 자리를 차지하고, 재생 명령을 보내도 파일을 받아 가지 않음 |
| 블루투스 앱을 끈 뒤 블루투스 재생 | 저절로 살아나지만 앱이 다시 뜨는 동안 **앞 2~3초가 잘림** |
| 30분 무음 시 블루투스 유지 | 시간 관계로 1분 만에 중지 → **미확인** |
| PC 마이크로 확인 | 마이크가 막혀 있어(−97 dB 디지털 무음) 불가, 사람이 귀로 확인 |

## 4. 농막 활용 설계

1. **음성으로 히터 켜기·끄기**: Shelly 플러그를 Matter로 구글홈에 등록. 음성 조작은 Pi에게 "사람이 바꾼 것"으로 보여 **수동 우선 시간(2시간)**이 받아 준다. 동파 위험이면 Pi가 다시 켠다([HEATER.md](../HEATER.md) "수동 우선 시간").
2. **Pi 알림을 Home Mini로(캐스트)**: Pi가 이미 만드는 알림 음성 파일을 같은 Wi-Fi의 Home Mini로 캐스트. 지금 블루투스 스피커처럼 30분 무음 뒤 꺼지는 문제가 없다(20분 시보가 필요 없어짐).
   - 대상 선택: 이름 "Living room" + 모델 "Google Home Mini"가 정확히 한 대일 때만.
   - Home Mini가 "Bluetooth Audio" 앱 중이면(사람이 폰 음악을 튼 경우) **그 앱을 먼저 끄고** 캐스트. 경고가 음악을 끊고 나오는 것이 맞는 동작.
   - 볼륨을 바꾸지 않는다(원래 값 유지). 필요하면 알림만 일시적으로 올리고 되돌린다.
3. **블루투스 스피커는 예비**: Home Mini가 아니라 원래 블루투스 스피커와만 페어링해 둔다(두 경로가 다른 기기라 서로 부딪치지 않음). 공유기가 죽었을 때 사용. 문장 앞에 **2~3초 무음이나 짧은 차임**을 붙여 앞부분 잘림을 막는다.
4. **음성으로 모드 바꾸고 상태 묻기**: Pi에 Matterbridge를 올려 가상 기기를 내보낸다.
   - 가상 스위치 "취침 모드", "난방 모드", "동파 모드" → "헤이 구글, 취침 모드 켜 줘" = Pi의 `취침` 명령.
   - 1층·다락·바깥 센서를 가상 온도계로 → "헤이 구글, 다락 온도 몇 도야?"
5. 덤: 폰에서 "방송하기"로 집→농막 음성 전달, 알람·타이머.

**주의**
- 데이터: 음성 명령·알림은 작지만 **음악 스트리밍과 기기 자체 업데이트**는 수백 MB → 월 6 GB 요금제에서 음악은 피하고 Mango에서 사용량 감시.
- 사생활: 항상 켜진 마이크. 비울 때는 마이크 스위치를 꺼도 캐스트 알림은 나온다.
- 오래된 기기(2017): 업데이트가 끊기면 Matter 지원이 줄 수 있음. 캐스트 재생은 오래 유지될 가능성이 큼.

## 5. 현장에서 확인할 것 / 남은 일

1. LTE 개통 후 Google Home 앱으로 Home Mini를 Mango Wi-Fi에 연결(사람, 1회).
2. **인터넷이 끊기고 공유기만 살아 있을 때** Pi의 로컬 파일 캐스트가 되는지.
3. 블루투스 스피커가 아닌 Home Mini를 블루투스로 쓸 일이 생기면 30분 무음 유지 여부.
4. Pi `alert_sound.py`에 캐스트 출력 추가(이름+모델 일치, 블루투스 앱이면 먼저 종료, 실패 시 블루투스 스피커로), 앞 무음 처리.
5. Shelly 플러그 Matter 등록과 음성 시험, Matterbridge 설치.
